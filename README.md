# Cadence — 로컬 우선 업무 생산성 콘솔

[![검사](https://github.com/unono915/cadence/actions/workflows/test.yml/badge.svg)](https://github.com/unono915/cadence/actions/workflows/test.yml)

> 얼마나 오래 앉아 있었는지가 아니라, **얼마나 온전한 시간을 만들었는지**를 보여주는 도구.

Windows 에서 실제로 무엇을 하며 시간을 보냈는지 자동으로 기록하고, 태스크·집중 세션과 엮어
"오늘 왜 일이 안 됐는지"에 답하는 하루/주간 리포트를 만들어 줍니다.
데이터는 전부 이 PC 안에만 있습니다. 계정도, 클라우드도, 외부 전송도 없습니다.

---

## 왜 만들었나

시간 관리 도구는 보통 둘 중 하나입니다.

- **할 일 목록** — 무엇을 할지는 알려주지만, 그게 왜 안 됐는지는 모릅니다.
- **시간 추적기** — 얼마나 썼는지는 알려주지만, 앱 이름을 나열할 뿐입니다.

생산성이 무너지는 진짜 원인은 대개 "시간이 부족해서"가 아니라 **시간이 잘게 쪼개져서**입니다.
같은 3시간이라도 20분씩 아홉 조각으로 흩어진 3시간과 90분 블록 두 개인 3시간은 전혀 다른 결과를 냅니다.

Cadence 는 그 차이를 측정합니다.

- **몰입 블록** — 15분 이상 끊기지 않고 이어진 생산 구간. 짧은 이탈(기본 2분)은 허용하되 몰입 시간으로 세지 않습니다.
- **연속성** — 같은 몰입 시간 중 블록 안에 들어간 비율.
- **파편화** — 시간당 앱 전환 횟수.
- **Cadence 점수** — 위 지표들을 하나의 0~100 값으로 압축.

## 빠른 시작

전제: **Node.js 22.5 이상**, Windows 10/11. 설치할 npm 패키지는 **없습니다** (의존성 0개).

```bash
cd cadence
npm start
```

터미널에 뜬 주소(`http://127.0.0.1:4321`)를 브라우저에서 엽니다.
Windows 라면 `start.cmd` 를 더블클릭해도 됩니다 — 서버를 켜고 브라우저까지 열어 줍니다.

먼저 화면을 둘러보고 싶다면 데모 데이터로 실행해 보세요 (실제 데이터와 완전히 분리됩니다).

```bash
npm run demo -- 21          # 21일치 가상 데이터를 저장소의 demo/ 에 만듭니다
CADENCE_DATA_DIR=./demo npm start
```

데모 생성기는 실제 데이터 폴더(`%LOCALAPPDATA%\Cadence`)를 가리키면 **거부합니다** —
기록을 통째로 지우고 다시 만드는 스크립트라, 되돌릴 수 없는 일은 한 번 더 막아 둡니다.

데모 데이터는 실제 쓰임에 가깝게 만듭니다 — 태스크가 주마다 생기고, 예상한 만큼 시간을 쓰면
끝나고, 오늘 몫의 계획이 남아 있습니다. 그래야 추정 정확도나 계획 실현 가능성 같은 화면이
**말이 되는 숫자**로 보입니다.

Windows PowerShell 에서는:

```powershell
$env:CADENCE_DATA_DIR=".\demo"; node scripts/seed-demo.mjs 21; node server/index.mjs
```

| **설정** | 추적기 제어, 개인정보 옵션, 목표·판정 기준, 카테고리와 규칙, 백업·복원·정리 |

### 단축키

`Ctrl`+`K` 명령 팔레트 · `1`–`5` 화면 이동 · `N` 빠른 태스크 추가 · `F` 집중 세션 시작/종료 ·
`I` 방해 1회 기록 · `←` `→` 날짜 이동 · `Alt`+`↑`/`↓` 태스크 순서 이동 · `Esc` 닫기

태스크 순서는 드래그로도 바꿀 수 있습니다. 드래그만 지원하면 키보드 사용자에게는 기능이
없는 것과 같으므로 두 방법을 함께 둡니다.

같은 이유로 **마우스로만 누를 수 있는 자리를 두지 않습니다.** `div` 나 표의 행에 클릭만
달아 두면 키보드로는 닿지도 누르지도 못하고, 화면 낭독기에는 "누를 수 있다" 는 사실 자체가
전달되지 않습니다 — 눈으로 보면 멀쩡해서 만드는 사람은 끝까지 모릅니다. 감쌀 수 있으면
버튼으로, 표의 행처럼 감쌀 수 없으면 역할과 키 처리를 함께 붙입니다.
눌린 상태도 색으로만 알리지 않습니다(`aria-pressed`). 둘 다 `test/no-html-sink.test.mjs`
가 지키고, 예외는 이유를 적어 목록으로 둡니다.

**쓰던 글은 한 번의 실수로 사라지지 않습니다.** 창은 배경을 누르거나 `Esc` 를 치면 닫히는데,
그 안에 아직 저장하지 않은 글이 있으면 첫 번째 누름은 닫지 않고 알려만 줍니다 —
태스크 메모 칸은 8천 자까지 받고 하루 마무리 회고도 그 안에서 쓰기 때문에, 빗나간 클릭
하나로 그걸 통째로 버리게 두지 않습니다. 이어서 한 번 더 누르면 닫힙니다.
'취소'·'닫기' 처럼 작정하고 누른 것은 그대로 바로 닫힙니다.

**화면이 기억해 둔 선택은 믿지 않고 읽습니다.** 리포트의 기간, 타임라인의 보기 방식 같은
값은 브라우저에 남는데, 그 값이 지금 고를 수 있는 것 중에 없으면 기본값으로 돌아갑니다.
예전에는 그대로 서버로 나가 400 을 받았고, 화면에는 '다시 시도' 단추만 남아 **눌러도
같은 값을 또 보내니 영원히 같은 자리에 머물렀습니다.** 브라우저 저장소를 직접 지우는 것
말고는 빠져나올 길이 없었습니다. 누가 손대지 않아도 그렇게 됩니다 — 다음 판에서 고를 수
있는 값이 바뀌면 옛 값을 들고 있던 사람만 조용히 갇힙니다.

입력칸은 서버가 받는 길이만큼만 받습니다(`web/lib/limits.js` 한 군데서 정하고 서버와
화면이 같이 씁니다). 다 쓰고 저장을 누른 뒤에야 "너무 깁니다" 를 보는 일은 막을 수 있는
실패입니다.

키보드로 옮겨 다닐 때는 지금 어디에 있는지 테두리로 표시합니다(마우스로 누를 때는 나오지 않습니다).
글자 색은 두 테마 모두 배경 대비 **4.5:1 이상**을 지킵니다 — 이 화면은 작은 흐린 글씨로
부가 정보를 많이 쓰는데, 대비가 모자라면 눈이 좋은 사람에게만 "차분한 회색" 입니다.
색을 고칠 때마다 사람이 계산기를 두드리게 하면 결국 안 하므로 `test/contrast.test.mjs` 가 계산합니다.

명령 팔레트에서는 화면 이동·날짜 이동·세션 조작·태스크 검색을 한 곳에서 합니다.
한글 초성으로도 찾습니다 (`ㅅㄴㅍ` → "성능 프로파일링").

### 하루를 다루는 방식

- **오늘 하기로 한 일** — 할 일 목록 전체가 아니라 오늘 끝낼 작정인 두세 가지만 골라 둡니다.
  하루가 흐트러졌을 때 돌아올 기준선입니다. 고르는 창에서 **바로 만들 수도 있습니다** —
  처음 쓰는 사람에게는 태스크가 하나도 없는데, "오늘 끝낼 일을 정하세요" 라고 권해 놓고
  "열려 있는 태스크가 없습니다" 한 줄만 보여 주면 시키는 대로 했더니 막다른 길이 됩니다.
- **지금 시작할 일** — 계획을 세워 둬도 아침에 화면을 열면 "그래서 뭐부터?" 에서 한 번 더
  멈춥니다. 남은 계획과 **당신의 골든타임**을 합쳐 하나를 골라 주고, 그 자리에서 시작합니다.
  규칙은 하나입니다 — **무거운 일을 가장 좋은 시간에.** 골든타임에 잡무를 하고 오후에 설계를
  붙잡는 것이 하루가 무너지는 흔한 방식이라서요. 골든타임 직전이면 짧은 것부터 치우게 하고,
  리듬을 알 만큼 기록이 없으면 시간대 이야기는 꺼내지 않고 우선순위만 봅니다.
- **계획 실현 가능성** — 남은 계획이 오늘 안에 들어가는지 **하루가 아직 고쳐질 때** 알려 줍니다.
  두 가지를 곱합니다: ① 최근 완료한 일에서 얻은 **추정 편향**(사람은 대개 자기 일을 적게 잡고,
  그 버릇은 꽤 일정합니다) ② 목표치가 아니라 **평소의 자기 자신**을 기준으로 한 남은 몰입 여력.
  "예상 3시간이지만 당신의 추정은 실제의 1.5배였고, 오늘 남은 여력은 2시간이라 2시간 30분 모자랍니다"
  까지 말합니다. 근거가 얕으면(추정 표본 3개 미만, 기준선 없음) 아무 말도 하지 않습니다.
- **집중 세션** — 시작하면 태스크가 자동으로 "진행 중"이 되고, 세션 구간의 활동 기록이 그 태스크에 붙습니다.
  끝나면 브라우저 알림·소리·탭 제목 카운트다운으로 알려 주고, 계획한 시간을 채웠다면 휴식을 권합니다.
- **이탈 알림** — 집중 세션을 걸어 둔 채 방해요소로 분류된 창에 2분 넘게 머물면(설정에서 조절,
  0 이면 끔) 그 순간 알립니다. 이 도구의 나머지는 전부 "끝난 뒤에" 알려 주지만, 새고 있을 때
  필요한 것은 기록이 아니라 그때의 한마디입니다. 새는 동안 Cadence 탭은 뒤에 있으므로
  **브라우저 알림**으로 보냅니다. 한 번 샌 동안 딱 한 번만 말하고, 일로 돌아오면 다시 셉니다 —
  휴식 세션 중에는 아무 말도 하지 않습니다.
- **시간 직접 추가** — 자동 추적이 놓친 오프라인 작업(회의·통화·종이 작업)을 채워 넣습니다.
  그 시간대의 **기존 기록을 대신합니다** — 그냥 한 줄 더 넣으면 자리비움 30분 위에 회의 30분이
  얹혀 하루가 한 시간 늘어나고, 활동·몰입·카테고리 배분이 전부 조금씩 부풀어 오릅니다
  (화면 어디에도 "겹쳤습니다" 라고 나오지 않아 아무도 눈치채지 못합니다).
  누르기 전에 무엇이 대체되는지 보여 줍니다.
- **자리비움 되묻기** — 15분 넘게 화면 앞을 떠난 구간을 하루에 한 번씩 되묻습니다.
  회의·통화·오프라인 검토를 표시해 두어야 하루가 실제대로 계산됩니다. 한 번 확인한 구간은 다시 묻지 않습니다.
- **하루 마무리** — 계획과 실제를 나란히 보고, 남은 것을 내일로 넘기고, 회고 한 줄을 남깁니다.
  정해진 시각(기본 18시)이 지나면 **하루에 한 번만** 알립니다 — 화면에 카드를 하나 더 붙이면
  잔소리가 되므로 알림 하나로 끝냅니다. 이미 마무리한 날이나 기록이 30분 미만인 날은 알리지 않습니다.
- **세션 자동 감지** — 세션을 켜는 걸 잊은 채 20분 넘게 몰입했다면, 끝난 직후 한 번만
  "기록으로 남길까요?"라고 묻습니다. 거절한 구간은 다시 묻지 않습니다.
- **주간 리뷰** — 지난주와 같은 일수끼리 비교하고(주중에 열어도 왜곡되지 않습니다),
  프로젝트 목표 달성률·골든타임·추정 정확도를 함께 본 뒤 **다음 주에 지킬 것 하나**를 정합니다.
  그 한 줄은 다음 주 월요일 노트에 자동으로 올라가고, **다음 리뷰에서 되짚습니다**
  ("지켰나요? 지켰다 / 반쯤 / 못 지켰다"). 약속을 받기만 하고 아무도 다시 묻지 않으면
  그 한 줄은 노트에 적히고 그걸로 끝입니다 — 한 번 물어야 다음 약속이 진지해집니다.
  답은 다시 그 주 노트에 남으므로, 자기 노트에서 흐름을 그대로 읽을 수 있습니다.
  지난주를 아직 돌아보지 않았다면 오늘 화면에서 한 번 권합니다 —
  리뷰는 알려주지 않으면 하지 않게 되므로.
- **멈춘 것을 알려 줍니다** — 자동 추적이 꺼져 있거나 프로브에 문제가 생기면 오늘 화면 맨 위에
  세워 알립니다. 추적이 멈춘 하루는 통째로 비는데, 화면은 "몰입 0분" 이라고만 말할 뿐
  그것이 "일을 안 했다" 인지 "기록이 안 됐다" 인지 구별해 주지 않기 때문입니다.
- **평소 대비** — 모든 핵심 지표에 최근 14일 중앙값 대비 증감을 함께 표시합니다.
  "몰입 4시간"은 그 자체로는 좋은지 나쁜지 알 수 없기 때문입니다. 평균이 아니라 중앙값을
  쓰므로 하루 몰아친 날이나 반차 낸 날이 기준선을 흔들지 않습니다.
- **업무 리듬** — 여러 주의 기록을 시간대·요일로 접어 **언제 몰입이 잘 되는지**를 찾아냅니다.
  단순 합계가 아니라 "그 시간에 자리에 있었을 때 몰입한 비율"로 보므로, 그냥 오래 앉아 있던
  시간대가 1등이 되지 않습니다. 관측일이 3일 미만인 시간대는 골든타임 후보에서 제외합니다.
  골든타임을 알면 회의를 어디로 미룰지가 정해집니다.
- **분류가 필요한 앱** — 미분류로 남은 시간은 몰입도·방해 비율 계산에서 통째로 빠져
  모든 지표를 조용히 깎습니다. 타임라인 맨 위에서 시간이 큰 앱부터 한 번 눌러 정리하면
  규칙이 되어 과거 기록까지 함께 바뀌고, 다음부터는 자동으로 분류됩니다.
- **되풀이되는 낱말 제안** — 브라우저 제목은 `"<페이지> - <사이트> - Chrome"` 이고 페이지 이름은
  매번 다릅니다. 제목을 하나씩 분류하면 오늘 것만 정리되고 내일 또 새 제목이 생깁니다 —
  미분류가 줄지 않는 진짜 이유가 이것입니다. 그래서 여러 제목에 **함께 나오는 조각**
  (`GitHub`, `관리 콘솔`, `Stack Overflow`)을 시간 순으로 뽑아 줍니다. 한 번 누르면 앞으로 생길
  제목까지 함께 잡습니다. 제목 두 개 이상에 나오는 것만 후보로 두고, 앱 이름 자체는 뺍니다
  (그건 앱 단위 규칙입니다). 실제로 후보 하나를 누르니 미분류가 146분 → 95분으로 줄었습니다.
- **구간 지정** — 타임라인 막대를 **가로로 끌면** 그 구간의 활동을 **한 번에** 태스크·카테고리로
  묶습니다 (시각을 직접 입력할 수도 있습니다). 막대를 그냥 누르면 그 기록 하나만 열립니다. 자동 추적은 창 제목이 바뀔 때마다 기록을 나누므로 두 시간짜리 작업 하나가
  수십 줄입니다. 한 줄씩 연결하라고 하면 아무도 하지 않고, 그래서 태스크별 시간은
  집중 세션을 켠 사람에게만 쌓입니다. 누르기 전에 **무엇이 바뀌는지**(몇 건, 몇 분, 어떤 앱)를
  먼저 보여 주고, 자리를 비운 구간은 건드리지 않습니다.
- **활동 전체 검색** — 창 제목·앱 이름으로 기간 전체를 뒤져 날짜별 합계로 보여 줍니다.
  "그 문서 언제 만졌더라", "이 건에 몇 시간 썼지" 같은 질문에 근거를 댈 수 있습니다.
  **메모도 함께 뒤집니다** — 이 도구에서 사람이 직접 쓴 것은 회고와 주간 약속뿐인데,
  정작 그것만 찾을 방법이 없었습니다. 맞은 줄만 골라 보여 주고, 누르면 그날로 넘어갑니다.
- **기간 리포트** — 시작·종료일을 직접 정해 프로젝트별·태스크별 시간을 뽑습니다.
  정산이나 월간보고처럼 주 단위로 딱 떨어지지 않는 자리를 위한 것입니다.
  마크다운으로 복사하거나 태스크별·활동별 CSV로 내려받을 수 있습니다.
- **프로젝트 주간 예산** — 프로젝트마다 "매주 몇 시간을 쓸 작정인지"를 정해 두면
  리포트에서 실적과 나란히 보여 줍니다. 투입 시간은 집중 세션과, 세션에 겹치지 않는
  태스크 연결 활동을 합쳐 계산합니다(같은 시간이 두 번 세어지지 않습니다).

## 어떻게 동작하나

```
 ┌──────────────┐   JSON Lines    ┌──────────────┐          ┌──────────────┐
 │ win-probe.ps1│ ──────────────► │ tracker.mjs  │ ───────► │  SQLite      │
 │ (Win32 API)  │  4초마다 샘플    │ 세그먼트 조립  │  즉시 기록 │  (WAL)       │
 └──────────────┘                 └──────────────┘          └──────┬───────┘
                                                                   │
 ┌──────────────┐    fetch/JSON   ┌──────────────┐                 │
 │ web/ (SPA)   │ ◄─────────────► │ node:http    │ ◄───────────────┘
 │ 바닐라 JS      │   127.0.0.1     │ 라우터 + 분석  │
 └──────────────┘                 └──────────────┘
```

**활동 추적**은 PowerShell 프로브 하나가 `GetForegroundWindow`, `GetWindowTextW`,
`GetLastInputInfo` 를 4초마다 읽어 JSON 한 줄씩 stdout 으로 흘려보내고, Node 가 그것을
세그먼트로 접어 SQLite 에 씁니다. 프로브는 **읽기 전용**입니다 — 창을 조작하지도, 키 입력
내용을 읽지도 않습니다(`GetLastInputInfo` 는 "마지막 입력이 언제였는지"만 알려줍니다).

몇 가지 설계 판단:

- **앱 이름은 실행 파일 단위로 캐시** — 표시 이름(FileDescription) 조회는 비싸서 캐시하는데,
  그 값은 실행 파일에 딸린 것이지 프로세스에 딸린 것이 아닙니다. 예전에는 pid 로 캐시했는데,
  윈도우는 pid 를 재사용합니다 — 짧게 살다 죽는 프로세스가 많은 기계를 며칠씩 켜 두면
  같은 번호가 다른 프로그램에 다시 붙고, 그때부터 그 시간이 **엉뚱한 앱 이름으로 기록됩니다.**
  화면에는 그럴듯한 이름이 뜨므로 아무도 눈치채지 못합니다.
- **소급 정산** — 자리비움은 임계값(기본 2분)을 넘겨야 감지되지만, 기록은 *마지막 입력 시각*에서
  끊습니다. 늦게 알아챘다고 해서 2분이 일한 시간으로 부풀지 않습니다.
- **공백은 기록하지 않음** — 절전·최대 절전으로 폴링이 끊긴 구간은 아예 비워 둡니다.
- **즉시 기록** — 세그먼트는 열릴 때 바로 INSERT 되고 폴링마다 종료 시각이 갱신됩니다.
  프로세스가 갑자기 죽어도 마지막 4초까지 남습니다.
- **데이터 폴더 잠금** — 같은 폴더에서 추적기가 둘 이상 돌지 않습니다. 심장박동 방식이라
  갑자기 죽은 프로세스의 잠금은 잠시 뒤 저절로 풀립니다(죽은 잠금에 발이 묶이지 않도록).
- **재시작 이어받기** — 서버를 다시 켤 때 진행 중이던 구간이 있으면 새로 만들지 않고 이어붙입니다.
  자리를 비운 채 서버를 여러 번 켜면 같은 시간이 실행 횟수만큼 중복 기록되기 때문입니다.
  이어받을 행은 id 가 아니라 **마지막으로 기록되던 시각**으로 고릅니다 — 업무일 경계에서
  구간을 쪼개면 전날 조각이 나중에 삽입되어 id 순서가 시간 순서와 어긋나기 때문입니다.
  공백이 길어 이어받기를 포기한 경우에도, **시작 시각과 내용이 같은 구간이 이미 있으면**
  그것을 잇습니다. 자리비움은 "마지막 입력 시각" 으로 소급해 열리므로 오래 비울수록
  중복이 확실해지는 구조였습니다(실제 기록에 같은 시각의 자리비움이 여덟 줄 쌓여 있었습니다).
  소급 시점은 밀리초 단위로 흔들리므로 2초 오차까지 같은 것으로 봅니다.
- **업무일은 04:00 시작** — 새벽 2시까지 이어진 작업이 다음 날로 잘리지 않게. 설정에서 바꿀 수 있습니다.
  시작 시각을 바꾸면 **이미 쌓인 기록의 날짜도 즉시 다시 매깁니다**. 그러지 않으면 한 화면 안에서
  '하루'의 뜻이 두 개가 되는데, 숫자는 멀쩡해 보여서 아무도 눈치채지 못합니다
  (15만 건 기준 0.4초). 노트와 "오늘 하기로 한 일"은 사람이 적은 날짜라 건드리지 않습니다.

**카테고리**는 이름이 아니라 **종류**(`deep`/`shallow`/`comms`/`meeting`/`break`/`distraction`/`other`)로
분석에 반영됩니다. "고객 응대" 같은 자기 업무 이름을 만들고 종류만 맞춰 주면 지표가 알아서 따라옵니다.
설정에서 추가·수정·삭제할 수 있고, 카테고리를 지워도 활동 기록은 남습니다(분류만 비워집니다).

**분류**는 규칙 목록(앱 이름 / 창 제목 → 카테고리)으로 이뤄집니다. 창 제목 규칙이 앱 규칙보다
우선하기 때문에 같은 브라우저라도 "GitHub" 는 개발로, "YouTube" 는 방해요소로 갈립니다.
타임라인에서 기록 하나를 눌러 **"이 앱을 항상 이렇게"** 를 누르면 규칙이 추가되고 과거 기록까지
한 번에 다시 분류됩니다. 설정에서 규칙의 우선순위·패턴·정규식 여부를 직접 고칠 수도 있습니다.

규칙을 과거 기록에 적용할 때는 새 규칙의 카테고리를 밀어 넣는 것이 아니라 **전체 규칙을 다시
태워** 결과를 씁니다. 그러지 않으면 나중에 만든 앱 규칙이 앞서 세워 둔 제목 규칙의 결과를
지워 버립니다.

규칙을 **고치거나 지울 때도** 과거 기록이 함께 따라옵니다. 추가할 때만 과거를 정리해 주면
규칙 목록과 실제 분류가 조용히 어긋나는데, 사용자는 그 사실을 알 방법이 없습니다.
바뀐 건수만 세어 알려 주므로 "아무것도 안 바뀌었는데 15만 건을 다시 분류했습니다" 같은
말은 나오지 않습니다 (15만 건 기준: 2만 5천 건이 바뀌는 수정에 1.6초, 바뀔 것이 없으면 0.6초).

한 앱에서 여러 일을 하는 경우(브라우저가 대표적)는 앱 단위로 묶으면 안 됩니다. "Chrome = 개발"
로 정하면 거기서 본 영상까지 몰입 시간이 됩니다. 그래서 창 제목이 5가지 이상인 앱은
**앱 단위 버튼을 주지 않고** 제목별로 나누도록 안내합니다. 그때 올라오는 제목 목록에는
**아직 분류되지 않은 것만** 담습니다 — 정리하러 들어온 사람에게 이미 정리된 줄을 보여 주면
가장 값진 클릭 몇 번을 아무것도 바꾸지 않는 데 쓰게 됩니다.

**목표가 그 사람의 일에 안 맞으면 그 사실을 말합니다.** 기본 목표는 하루 3시간 몰입인데,
그건 책상 앞이 일터인 사람을 전제한 값입니다. 수업이 하루 대부분인 교사, 현장을 도는
사람에게는 컴퓨터 앞이 하루 한 시간일 수 있습니다. 그런 사람에게 매일 "목표의 20%"
라고 말하면, 도구가 알려 주는 것은 일하는 방식이 아니라 목표가 틀렸다는 사실뿐입니다.
그래서 며칠치 중앙값이 목표의 절반에도 못 미치면, 오늘을 나무라는 대신 **목표를 중앙값에
맞춰 조정하라고** 권합니다. 표본이 3일 미만이면 꺼내지 않습니다 — 하루 이틀 적었다고
기준을 무너뜨리면 그건 도구가 아니라 변명이 됩니다.

오늘 화면의 **"분류하러 가기"** 는 타임라인으로 옮겨 준 뒤 **가장 큰 미분류 앱의 정리창을
곧바로 엽니다.** 예전에는 화면만 옮겨 주고, 거기서 다시 카드를 찾아 "제목별로 나누기" 를
눌러야 했습니다 — 이 앱에서 가장 값진 동작인데 가는 길이 가장 길었습니다.

**손으로 정한 분류는 규칙이 덮지 않습니다.** 구간을 지정하거나 기록 하나를 고쳐 카테고리를
정하면 그 기록에 표시가 남고, 그 뒤 어떤 규칙을 만들어도 그대로 있습니다. 규칙은 앱과 창 제목만
보지만 사람은 그 시간에 실제로 무엇을 했는지 알기 때문입니다. 다시 규칙에 맡기고 싶으면
카테고리를 "분류 없음" 으로 두고 저장하면 됩니다.

**기본 규칙은 판(版)으로 관리합니다.** 예전에는 첫 실행 때만 심었기 때문에, 기본 규칙을
아무리 손봐도 이미 쓰고 있던 사람에게는 영원히 닿지 않았습니다. 이제는 어느 판까지 심었는지
적어 두고 그 뒤에 더해진 것만 들여보냅니다 — 일부러 지운 규칙은 되살아나지 않고, 같은 패턴을
손으로 먼저 만들어 두었다면 그쪽이 남습니다. 들어온 규칙은 과거 기록에도 적용합니다.

**자리비움 되묻기의 빠른 버튼은 그 사람이 쓰는 말을 배웁니다.** 처음에는 회의·오프라인
작업·학습·휴식 넷이지만, 자리를 비우는 이유는 직업마다 다릅니다 — 교사에게는 대부분이
'수업' 이고 영업에게는 '외근' 입니다. 한 번 "직접 입력" 으로 적어 두면 그 다음부터는
그것이 버튼이 되고, 많이 쓴 순서로 앞에 섭니다. 카테고리가 사라진 이름표는 빠집니다 —
눌러도 미분류가 되는 버튼은 없느니만 못하기 때문입니다.

**타임라인의 '합쳐 보기'** 는 같은 앱을 이어서 쓴 구간을 한 줄로 접습니다. 자동 추적은 창 제목이
바뀔 때마다 기록을 나누므로, 접지 않으면 30분 작업이 스무 줄로 흩어져 오히려 안 보입니다.
접은 구간의 길이는 조각들의 단순 합이 아니라 **합집합**으로 셉니다 — 수동 입력이 추적 기록과
겹쳐도 같은 시간이 두 번 세어지지 않도록.

## 개인정보

- 서버는 **127.0.0.1 에만 바인딩**됩니다. `Host` 헤더와 `Origin` 을 검사해 DNS 리바인딩과
  외부 페이지에서의 접근을 막습니다.
- 외부로 나가는 네트워크 요청이 **하나도 없습니다**. npm 의존성도 0개입니다.
  응답에 `Content-Security-Policy: default-src 'none'` 을 붙여 브라우저 쪽에서도 막습니다.
- CSV 내보내기는 **엑셀 수식 주입**을 막습니다. 창 제목이 `=` 나 `@` 로 시작하면 엑셀은 그것을
  수식으로 읽는데(`=cmd|'/c ...'!A1` 은 실행까지 갑니다), 창 제목은 다른 프로그램이 정합니다.
  위험한 글자로 시작하는 칸 앞에 작은따옴표를 붙여 글자로 못박습니다. UTF-8 BOM 도 함께 붙여
  엑셀에서 한글이 깨지지 않게 합니다.
- 창 제목에서 **보이지 않는 글자**를 걷어 냅니다. 방향 뒤집기(U+202E)를 넣으면 화면에서
  `file<RLO>gnp.exe` 가 `fileexe.png` 로 보이고, 폭 없는 글자를 끼우면 서로 다른 제목이
  똑같아 보입니다. 창 제목은 다른 프로그램이 정하므로, 시간을 어디에 썼는지 읽는 도구에서
  제목을 잘못 읽게 만드는 것 자체가 기록을 못 믿게 만드는 일입니다.
- 화면 코드에는 `innerHTML` 이 **한 군데도** 없습니다. 이 앱은 다른 프로그램이 정한 창 제목을
  그대로 그리므로, 주입 통로가 하나라도 있으면 아무 프로그램이나 창 제목으로 이 화면에서
  코드를 실행할 수 있습니다. `test/no-html-sink.test.mjs` 가 이 규칙을 지킵니다.
- 분류 규칙에 정규식을 쓸 수 있는데, 저장하기 전에 **되짚기가 폭발하는 패턴인지 실제로 돌려
  확인**합니다. `(a+)+$` 같은 것을 어디선가 복사해 붙이면 그 뒤로 모든 활동이 이 정규식을
  거치면서 서버가 통째로 멈춥니다(자바스크립트 정규식에는 시간 제한이 없습니다).
  막히면 이유가 화면에 뜹니다.
- 화면에서 `hidden` 은 **어떤 CSS 규칙보다 우선**하도록 못박아 두었습니다
  (`[hidden] { display: none !important }`). 브라우저 기본값은 작성자 규칙에 지기 때문에,
  `.modal-root { display: grid }` 한 줄로 닫힌 모달 배경이 화면 전체에 깔린 채 남아
  **앱의 모든 클릭을 삼킨** 적이 있습니다. 화면은 멀쩡해 보였고 오류도 나지 않았습니다.
- 응답이 없는 연결을 오래 붙잡아 두지 않습니다 (`requestTimeout` 60초, 헤더 10초).
  `Content-Length` 만 적고 본문을 안 보내면 요청 처리가 그대로 멈춰 서기 때문입니다.
- 창 제목이 부담스럽다면 **설정 → 창 제목 수집 끄기**. 앱 이름만 기록됩니다.
  끄는 것은 앞으로만 막지만, **이미 쌓인 것도 지울 수 있습니다** — 설정 → 데이터 →
  **기록된 창 제목 지우기**(끌 때도 그 자리에서 물어봅니다). 문서 이름이나 거래처 이름이
  창 제목에 그대로 들어가 있다는 걸 뒤늦게 알아차리는 쪽이 보통이라, 지울 방법이 없으면
  남는 선택은 데이터베이스를 통째로 버리는 것뿐이고 그러면 몇 달치 기록을 함께 잃습니다.
  제목만 비우고 시간·앱·분류는 그대로 두므로 **지금까지의 숫자는 하나도 달라지지 않습니다**
  (다만 창 제목으로 판단하는 규칙을 지난 기록에 다시 적용할 수는 없게 됩니다).
  되돌릴 수 없는 일이라 지우기 전에 사본을 남깁니다.
- 데이터는 단일 SQLite 파일에 있습니다. 위치는 서버 시작 시 터미널에 표시되며, 기본값은
  `%LOCALAPPDATA%\Cadence\cadence.db` 입니다. 파일을 지우면 그걸로 끝입니다.
  WAL 을 2분마다(그리고 종료할 때) 본 파일에 넘기므로 `cadence.db` 하나만 복사해도
  최근 기록이 함께 갑니다. 서버가 돌고 있는 중이라면 **전체 백업 (JSON)** 쪽이 확실합니다.
- 설정 → **전체 백업 (JSON)** 으로 언제든 통째로 가져갈 수 있고, **백업 가져오기**로 되돌릴 수 있습니다.
  덮어쓰기 직전에는 데이터베이스 사본이 자동으로 저장됩니다 (최근 5개 유지).
  가져올 때 **숫자여야 할 자리에 숫자가 들어 있는지** 확인하고, 아니면 아무것도 바꾸지 않고 멈춥니다 —
  SQLite 는 타입이 느슨해서 그냥 받아들이는데, 그러면 그 뒤로 시각 계산이 전부 NaN 이 되고
  어디서부터 잘못됐는지 알 수 없게 됩니다.
  **지난 판에서 만든 백업도 열립니다** — 그 뒤에 생긴 열은 스키마에 적힌 기본값으로 채웁니다.
  이걸 안 하면 열을 하나 더할 때마다 그 전 백업이 통째로 복원되지 않는데, 백업의 값어치는
  "옛것도 열린다" 는 데 있으므로 그건 백업이 조용히 망가진 것과 같습니다
  (`test/backup-schema.test.mjs` 가 지킵니다).
- 서버가 떠 있는 동안 **하루에 한 번 사본**을 자동으로 남깁니다 (같은 폴더의
  `cadence-backup-<시각>.db`, 최근 5개 유지). 정리 대상은 **우리가 찍은 이름 모양**뿐입니다 —
  같은 폴더에 손으로 넣어 둔 `cadence-backup-중요.db` 같은 파일은 건드리지 않습니다.
  시계가 뒤로 가도(서머타임·NTP 보정) 사본 만들기가 멈추지 않습니다. 실수로 지우거나 파일이 깨져도 최악의 경우 하루치만 잃습니다.
  다만 사본은 데이터베이스와 **같은 디스크**에 있습니다 — 디스크 자체가 죽으면 함께 사라지므로,
  진짜 백업은 **전체 백업 (JSON)** 으로 다른 곳에 내보내 두세요.
  그건 사람이 기억해야 하는 일이고 사람은 기억하지 않으므로, 설정 → 데이터에
  **마지막으로 받아 간 때**를 적어 둡니다 ("한 번도 없습니다" / "3일 전" / 2주가 지나면 경고).
  잔소리를 하려는 게 아니라, "한 번도 없음" 과 "그저께" 는 완전히 다른 상태인데
  지금까지는 그 둘을 구별할 방법이 화면에 없었기 때문입니다.
- 기록이 쌓여 부담스러우면 설정 → **오래된 기록 정리**로 활동 기록만 잘라 낼 수 있습니다.
  태스크·세션·노트는 그대로 남습니다.

## 뭔가 안 될 때

- **"데이터 폴더를 쓸 수 없어 시작하지 못했습니다"** → 폴더 경로와 이유를 함께 알려 줍니다
  (경로 오타, 연결이 끊긴 네트워크·외장 드라이브, 권한, 디스크 공간). `CADENCE_DATA_DIR` 로
  다른 폴더를 지정하거나 권한을 고치면 됩니다. 예전에는 이 경우 Node 의 원시 스택이
  창 가득 뜨고 끝이었습니다 — `start.cmd` 로 띄운 사람에게는 그것이 전부였습니다.
- **"데이터베이스를 열지 못해 시작하지 못했습니다"** → 파일이 깨졌거나(정전 뒤 잘림,
  동기화 폴더의 충돌 사본) 다른 프로그램이 붙잡고 있는 경우입니다. 같은 폴더의
  `cadence-backup-<시각>.db` 를 `cadence.db` 로 복사하면 그 시점으로 되돌아갑니다.
  **원본은 지우지 말고 다른 이름으로 옮겨 두세요** — 그 안에 기록 전부가 들어 있고,
  깨진 파일에서도 되살릴 여지가 남습니다.
- **기록이 안 쌓입니다** → 설정 → 자동 추적 → **진단**. 프로브를 한 번 돌려 어디서 막혔는지
  (PowerShell 부재, 실행 정책, 보안 소프트웨어) 짚어 주고, 잠금 화면처럼 **프로브는 멀쩡한데
  기록될 것이 없는 상태**도 함께 알려 줍니다.
  프로브는 이미 `-ExecutionPolicy Bypass` 로 띄우므로 사용자 계정 정책은 문제가 되지 않습니다.
  그래도 막힌다면 조직 정책(그룹 정책)이나 보안 소프트웨어 쪽이며, 진단 결과에 실제 오류 메시지가
  그대로 나옵니다.
- **분류가 엉뚱합니다** → 타임라인에서 기록을 눌러 카테고리를 고치고 **"이 앱을 항상 이렇게"**.
  규칙이 생기고 과거 기록까지 다시 분류됩니다.
- **기록이 이상해 보입니다** → 설정 → 데이터. 어중간한 행(끝이 시작보다 이르거나, 길이가
  시각과 맞지 않거나, **시각이 숫자가 아니거나**, **시간이 겹치거나**, 창을 닫은 채 며칠
  열려 있는 세션)이 있으면 그때만 정리 버튼이 뜹니다. 정리 전에 사본이 저장됩니다.
  겹침 정리는 손으로 넣은 기록을 남기고, 나머지는 앞선 기록이 끝난 뒤로 밀어 **겹친 부분만**
  덜어 냅니다. 시각 순으로 한 번만 훑으므로 사슬처럼 얽혀 있어도 한 번에 끝납니다
  (15만 행에 겹침 1만 7천 쌍 기준 1초). 집중 세션도 같은 방식으로 봅니다 — 이 앱은 세션을
  한 번에 하나만 열므로, 겹친 세션은 밖에서 들어온 것이고 태스크 투입 시간을 두 번 세게 만듭니다.
- **포트가 이미 사용 중입니다** → 대개는 시작프로그램으로 이미 떠 있는 것입니다. 그럴 때는
  "이미 실행 중입니다" 라고 알리고 조용히 물러납니다 — 브라우저만 열면 됩니다.
  정말 다른 프로그램이 쓰고 있다면 `CADENCE_PORT` 를 바꿔 실행하세요.
  이때 **같은 데이터 폴더에서 추적기가 둘 돌지는 않습니다** — 나중에 뜬 쪽은 추적을 시작하지
  않고 이유를 알려 줍니다. 둘이 같은 활동을 각자 기록하면 하루 합계가 조용히 두 배가 됩니다.
- **콘솔 없이 돌리는데 뭔가 이상합니다** → 설정 화면 맨 위에 최근 서버 오류가 있으면 나타납니다.
  전체 기록은 데이터 폴더의 `cadence-errors.log` 에 남습니다(512KB 를 넘으면 앞부분을 잘라 냅니다).
  개인정보가 새지 않도록 활동 내용은 담지 않고 오류 메시지와 발생 위치만 남깁니다.

## 로그인 시 자동 실행 (선택)

서버가 켜져 있어야 기록이 쌓입니다. 로그인할 때 콘솔 창 없이 자동으로 띄우려면:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1
```

사용자 계정의 시작프로그램 폴더에 바로가기 하나를 만들 뿐입니다 — 관리자 권한도, 레지스트리 변경도 없습니다.
해제는 `-Remove` 를 붙여 다시 실행하면 됩니다.

## 개발

```bash
npm test        # node:test — 시간 계산, 추적기 상태 기계, 분석 로직, HTTP API, 기동·종료
npm run test:clock   # 같은 검사를 하루 열세 시각에 다시 (아래 '검사의 종류')
npm run dev     # 파일 변경 시 자동 재시작
```

의존성이 없으므로 빌드 단계도 없습니다. `web/` 아래 파일은 브라우저가 그대로 읽습니다.

```
server/
  index.mjs          HTTP 서버, 보안 헤더, 종료 처리
  lib/               config · db(마이그레이션) · http · time · text · validate · categorize
  api/               tasks · focus · activity · analytics · backup · misc · routes
  tracker/           win-probe.ps1 (Win32 프로브) · tracker.mjs (세그먼트 조립)
web/
  app.js             셸: 라우팅, 상단 바, 단축키, 폴링
  lib/               dom · api · store · format · charts(SVG) · ui · insights · notify · sortable
  views/             today · tasks · timeline · reports · settings
                     daily-plan · weekly-review · gaps · unclassified · palette
                     activity-search · task-item · quick-add
test/                time · dst(타임존) · boot(기동·종료) · tracker · analytics · api
                     성질 검사 · 회귀 방지 그물
scripts/             seed-demo.mjs (데모 데이터) · autostart.ps1 (자동 실행 등록)
                     clock-sweep.mjs (하루 여러 시각에 검사 돌리기)
```

데이터베이스 스키마는 `server/lib/db.mjs` 의 `MIGRATIONS` 배열로 관리합니다. 배열에 SQL 을
**추가만** 하고 기존 항목은 고치지 않습니다 — `PRAGMA user_version` 이 적용 지점을 기억합니다.
SQL 로 표현하기 어려운 손질은 함수로 넣을 수 있고, 트랜잭션 안에서 도는 것은 같습니다.

`test/migrations.test.mjs` 는 **첫 판 스키마로 DB 를 만들어** 지금까지 한 번에 올라오는지
봅니다. 마이그레이션은 하나씩 보면 다 맞는데 이어 돌릴 때 어긋나는 일이 있고, 그 상황을
실제로 겪는 사람은 오래 쓰다가 오랜만에 업데이트한 사람 — 잃을 기록이 가장 많은 사람입니다.
"돌긴 돌았다" 가 아니라 각 마이그레이션이 **적어 둔 일을 실제로 했는지**까지 확인합니다.

### 같은 것이 두 군데 있으면 검사가 붙듭니다

이 저장소에서 가장 많이 나온 결함은 논리 오류가 아니라 **정의가 갈라진 것**이었습니다.
같은 개념이 두 곳에 적혀 있으면 한쪽만 바뀌고, 그 순간 화면은 멀쩡해 보이면서 숫자만 어긋납니다.
주석에 "같은 규칙" 이라고 적어 두는 것으로는 지켜지지 않아서, 짝마다 검사를 하나씩 붙여 뒀습니다.

| 갈라질 수 있는 짝 | 어긋나면 | 지키는 검사 |
| --- | --- | --- |
| 업무일 계산 (서버 · 화면 · SQL) | 화면이 엉뚱한 날짜를 묻고, 점검이 멀쩡한 행을 잡는다 | `time` · `dst` |
| 시간 표기 (`humanDuration` · `dur`) | 리포트는 "2시간 15분", 화면은 "2시간 14분" | `time` |
| 점수 배점 (서버 · 화면 막대) | 막대가 칸을 넘거나 늘 짧게 나온다 | `api` |
| 카테고리 종류 · 화면 이름표 | 설정에 영문 키가 그대로 나온다 | `api` |
| 태스크 투입 시간 (네 경로) | 같은 태스크가 화면마다 다른 시간 | `task-time` |
| 백업 열 목록 · 실제 스키마 | 내보내기가 조용히 성공하며 값만 사라진다 | `backup-schema` |
| 설정 키 (기본값 · 파서 · 화면) | 저장은 되는데 반영이 안 된다 | `api` |
| 표본 기준 (화면 3곳 · 내보내기) | 한 건짜리 배율이 주간보고에 근거처럼 실린다 | `api` · `task-time` |
| 밝은 테마 색 (두 블록) | 같은 밝은 화면인데 색이 다르다 | `contrast` |
| 입력 길이 상한 (서버 검사 · 화면 `maxlength`) | 다 쓰고 저장을 누른 뒤에야 빨간 오류를 본다 | `limits` |
| 판정 기준값 (설정 · 화면 문장) | 40분으로 바꿔 뒀는데 화면은 계속 "15분 이상" 이라고 쓴다 | `api` |

열을 추가할 때는 `server/api/backup.mjs` 의 `BACKUP_TABLES` 도 함께 고쳐야 합니다.
빠뜨리면 내보내기·가져오기가 **조용히 성공하면서 그 열의 값만 사라집니다**.
`test/backup-schema.test.mjs` 가 실제 스키마와 백업 목록을 대조해 이를 막습니다.

화면마다 자기 컨테이너를 받습니다. 뷰는 데이터를 받아 오는 동안 자기 root 에 다시 그리는데,
모두가 같은 요소를 쓰면 화면을 빠르게 넘길 때 **이전 화면의 늦은 그리기가 새 화면을 덮어씁니다**.
같은 이유로 상단 바의 타이머는 구조를 다시 만들지 않고 숫자만 갈아 끼웁니다 —
매초 다시 그리면 그 안의 버튼에 둔 키보드 포커스를 매초 잃기 때문입니다.

성능은 실제 규모로 재서 맞췄습니다. 15만 건(21MB, 실제 추적 반년치 모양)에서 모든 화면 조회가
0.5초 안에 끝나고, 30MB 백업 왕복이 4.3초입니다. 태스크별 시간 집계는 인덱스를 타는지까지
테스트로 고정해 두었습니다 — 인덱스가 빠지면 기록이 쌓일수록 **조용히** 느려지기 때문입니다.

### 검사의 종류

정해 둔 상황을 확인하는 검사 말고도, 세 가지를 따로 둡니다.

- **기동·종료 검사** (`test/boot.test.mjs`) — 서버를 **진짜로 띄워** 봅니다. 포트가 막혔을 때
  "이미 켜져 있습니다"(우리 것이면 조용히 물러남)와 "다른 포트를 쓰세요"(남의 것이면 실패)를
  가르는 분기, 종료 신호를 받고 나가는지, 나간 뒤에도 기록이 남는지,
  브라우저를 못 열어도 서버가 살아 있는지(`spawn` 의 실패는 예외가 아니라 이벤트로 오기 때문에,
  받아 두지 않으면 브라우저를 못 여는 것만으로 프로세스가 죽습니다). 사용자가 가장 흔하게
  겪는 경로(아이콘을 두 번 누르기, 창 닫기)인데 모듈을 불러오는 방식으로는 닿지 않습니다.
- **타임존 훑기** (`test/dst.test.mjs`) — 서머타임이 있는 지역을 **실제로 띄워** 봅니다.
  이 도구를 만든 자리(한국)에는 서머타임이 없어서, 업무일 계산이 시각에서 네 시간을 빼는
  방식이어도 아무 문제가 없었습니다. 있는 곳에서는 전환일에 어긋납니다 — 미국 동부 기준
  2026-03-08 04:30 이 `2026-03-07` 로 매겨졌는데 그 업무일의 범위는 03-07 04:00 ~
  03-08 04:00 이라 그 시각을 담지 못합니다. 기록은 DB 에 남아 있는데 **어느 날의 조회에도
  걸리지 않아, 한 해 두 번 한 시간씩 조용히 사라집니다.** 여기서만 돌려서는 절대 만날 수
  없으므로, `TZ` 를 바꾼 자식 프로세스를 띄워 한 해 전체를 훑습니다.
  업무일 계산은 사실 **세 군데**에 있습니다 — 서버(`time.mjs`), 화면(`format.js`), 그리고
  무결성 점검이 15만 행을 자바스크립트로 끌어오지 않으려고 쓰는 **SQL 식**. 셋이 어긋나면
  각각 다른 방식으로 조용히 망가집니다: 화면은 서버에 엉뚱한 날짜를 물어보고, 점검은
  멀쩡한 행을 "날짜가 틀렸다" 고 잡은 뒤 고치기가 되돌려 놓아 **아무리 눌러도 사라지지 않는
  경고**가 됩니다. 그래서 셋을 한 해 전체에 걸쳐 나란히 돌려 봅니다.
- **시각 훑기** (`npm run test:clock`) — 검사를 하루 여러 시각에 돌려 봅니다.
  이 도구가 다루는 것은 전부 시각이고, 하루는 자정이 아니라 **04시**로 갈립니다.
  그런데 검사는 대개 `Date.now()` 에서 몇 시간을 더하고 빼서 표본을 만들기 때문에,
  돌리는 시각에 따라 표본이 업무일 경계를 넘어가 **새벽에만 실패하는 검사**가 생깁니다.
  실제로 그런 것이 셋 있었고, 자정을 넘겨 작업하다 처음 드러났습니다.
  `Date.now()` 를 몇 시간씩 옮겨 놓고 전체를 돌리므로 빠르고, 우연을 기다리지 않습니다.
  (같은 훑기가 제품 쪽 결함도 하나 잡았습니다 — 시계가 뒤로 가면 자동 사본이
  영영 멈추는 문제였습니다.)

- **성질 검사** (`test/analytics-properties.test.mjs`) — 무작위 하루 수백 개를 만들어
  "어떤 입력에도 반드시 참이어야 하는 것"을 겁니다. 몰입 시간이 블록 길이보다 길 수 없고,
  몰입이 늘었는데 점수가 떨어질 수 없고, 앱 전환이 잦아졌는데 점수가 오를 수 없습니다.
  값이 얼마인지가 아니라 **말이 되는 값인지**를 봅니다. 실패하면 그 하루를 그대로 되살릴
  씨앗을 함께 찍습니다.
- **회귀 방지 그물** — 사람이 리뷰로 지키기 어려운 규칙을 검사에 맡깁니다.
  화면 코드에 HTML 주입 통로가 없는지(`no-html-sink`), 쓰이지 않는 export·import 가
  없는지(`no-dead-code`), 등록된 모든 GET 경로가 500 을 내지 않는지(`routes-smoke`),
  브라우저가 읽는 파일이 문법적으로 성립하는지(`no-dead-code` — `web/` 은 빌드 단계가 없어서
  문법 오류가 나도 아무 말 없이 그 화면 전체가 죽습니다),
  눌린 상태를 색으로만 알리는 버튼이 없는지(`no-html-sink`),
  태스크 투입 시간이 네 군데에서 같은 값인지(`task-time`), 백업 목록이 스키마와 맞는지
  (`backup-schema`), 손으로 정한 분류를 규칙이 덮지 않는지(`pinned`), 기본 규칙의 판이
  올라갈 때 일부러 지운 규칙이 되살아나지 않는지(`defaults-upgrade`), `hidden` 속성이
  어떤 CSS 규칙보다 우선하는지(`no-html-sink`).
  각각 **고의로 결함을 넣어** 검사가 실제로 잡는지 확인했습니다.
- **못된 값 넣어 보기** (`test/query-fuzz.test.mjs`) — 등록된 모든 GET 경로에 말이 안 되는
  질의 인자를 8천 번 넣어 봅니다(빈 값, 음수, 아주 큰 수, 없는 날짜, 5천 자, 경로 거슬러
  올라가기, 같은 인자 두 번…). 보는 것은 "거절하느냐" 가 아니라 **어떻게 거절하느냐** 입니다.
  400 이면 좋고, 200 이면 안전한 기본값으로 되돌렸다는 뜻입니다. 500 은 처리하지 못한
  예외라는 뜻이고, 그때 화면은 "서버가 내려갔습니다" 라고만 말해 사용자는 자기가 무엇을
  잘못했는지 영영 모릅니다. 응답에 파일 경로나 스택이 섞여 나가지 않는지도 함께 봅니다.
  본문이 망가진 POST(잘린 JSON, 400겹 중첩 배열, 20만 자)도 같은 기준으로 봅니다.
- **그림이 조용히 비지 않는지** (`test/charts.test.mjs`) — 차트 코드가 하는 일은 숫자를
  좌표로 바꾸는 것뿐인데, 여기서 틀려도 **예외가 나지 않습니다.** `width="NaN%"` 나
  `opacity="NaN"` 은 브라우저가 조용히 무시하고 빈 자리를 남깁니다 — 화면은 멀쩡히 뜨고
  콘솔도 깨끗하고, 다만 막대가 안 보입니다. 열어 봐도 "오늘은 기록이 없나 보다" 로 읽히니
  틀린 값을 보여 주는 것보다 나쁠 수도 있습니다. 게다가 `Math.max` 는 NaN 하나에 통째로
  물들기 때문에 **이상한 값 하나가 그 그림 전체를 지웁니다.** 그래서 못된 값을 잔뜩 넣고
  나온 그림에 `NaN`·`undefined` 가 없는지 봅니다. 표본은 **서버가 실제로 보내는 모양
  그대로** 씁니다 — 처음에 필드 이름을 대충 지어 넣었더니 멀쩡한 코드가 실패했습니다.
  모양이 다른 표본으로 도는 검사는 아무것도 지키지 않으면서 사람을 엉뚱한 데로 보냅니다.
  (`test/dom-stub.mjs` 는 `dom.js` 가 실제로 쓰는 것만 흉내 낸 받침대입니다. 브라우저가
  아니므로 일부러 작게 두었습니다 — 흉내가 커질수록 "검사에서는 되는데 화면에서는 안 되는"
  자리가 늘어납니다.)
- **다른 플랫폼에서도 돌려 본다** (`.github/workflows/test.yml`) — 푸시마다 windows 와
  ubuntu 에서, Node 22 와 24 로 전체를 돌립니다. ubuntu 는 쓰는 자리가 아니라 **대조군**입니다 —
  리눅스에서만 깨진다면 그건 "윈도우에서 우연히 되고 있었다" 는 뜻이기 때문입니다.
  붙이자마자 두 가지가 걸렸습니다. 하나는 플랫폼 분기 때문에 리눅스에서는 닿을 수조차 없던
  검사였고(윈도우 전용으로 표시), 다른 하나는 **자동 사본이 자기 그림자를 보고 하나 더
  만들던 실제 결함**이었습니다 — 파일 시각은 밀리초 아래까지 남는데 `Date.now()` 는 잘라
  버려서, 방금 만든 사본이 0.3ms '미래' 로 보이고 그걸 "시계가 뒤로 갔다" 로 읽었습니다.
  파일 시각이 촘촘한 리눅스에서만, 그것도 가끔만 드러납니다.
  매주 한 번은 시각 훑기도 CI 에서 돕니다(5분이라 푸시마다 돌리기에는 무겁고, 사람이
  기억해서 돌리지도 않습니다).
  워크플로 로그는 저장소 관리자만 볼 수 있어서, 실패한 검사와 세부 내용을 공개로 읽히는
  주석으로 내보냅니다 (`.github/report-failures.mjs`).
- **소스 위생** (`test/source-hygiene.test.mjs`) — 눈에 보이지 않는 문자가 섞였는지 봅니다.
  실제로 `categorize.mjs` 안에 NUL 바이트 두 개가 글자 그대로 박혀 있었습니다. 동작은
  멀쩡했지만 그 순간부터 그 파일이 도구들에게 **바이너리**로 보여서, `grep` 은
  "Binary file matches" 만 내놓고 diff 도 내용을 보여 주지 않았습니다 — 가장 손이 많이 가는
  파일 하나가 조용히 검색과 리뷰 밖으로 빠져나가 있었습니다. 사람이 읽어서는 찾을 수
  없는 종류라(보이지 않으므로) 검사에 맡깁니다. UTF-8 로 읽히는지, BOM 이 붙지 않았는지도
  함께 봅니다.

## 지표 정의

| 지표 | 정의 |
| --- | --- |
| 활동 시간 | 자리비움을 제외한 포그라운드 시간 합계 |
| 몰입 시간 | 카테고리 종류가 `deep` 인 활동의 합계 |
| 몰입 블록 | 15분 이상 이어진 몰입 구간. 2분 이하의 이탈은 블록을 깨지 않지만 몰입 시간에 포함되지도 않음 |
| 연속성 | 블록 안에 들어간 몰입 시간 / 전체 몰입 시간 |
| 앱 전환 | 서로 다른 앱으로 넘어간 횟수 (자리비움 전후는 세지 않음). 시간당 값은 **활동 시간**으로 나눈 것이라, 잠깐씩만 앉은 날에는 쉽게 커집니다 — 그래서 활동이 2시간에 못 미치면 이 숫자로 조언하지 않습니다 (재는 것과 훈수를 두는 것은 다른 일입니다) |
| 추정 정확도 | 완료한 태스크의 (실제 투입 시간 / 예상 시간) 중앙값. 1.0 이면 정확. 표본 3개 미만이면 중앙값을 내지 않는다 |
| 평소(기준선) | 최근 14일 중 활동 30분 이상인 날들의 중앙값. 표본 3일 미만이면 표시하지 않음 |
| 태스크·프로젝트 투입 시간 | 집중 세션 시간 + 세션과 겹치지 않는 "태스크에 연결된 활동" 시간. 태스크 목록·기간 리포트·프로젝트 집계·추정 정확도가 **모두 같은 정의**를 쓴다 (`test/task-time.test.mjs` 가 네 값이 일치하는지 검사) |
| 완주한 세션 | 계획한 시간의 8할 이상을 채우고 끝낸 집중 세션. 그 전에 끄면 중단으로 남습니다 — 종료 버튼도 누르기 전에 어느 쪽인지 알려 줍니다 |
| 겹치는 기록 | 같은 시각을 덮는 두 기록. 집계는 단순 합이라 그만큼 하루가 길어진다. 설정 → 데이터에서 찾아내고 고칠 수 있다 |
| 시간대 몰입 비율 | 그 시간대의 (몰입 시간 / 활동 시간). 절대량이 아니라 비율로 봐야 골든타임이 드러난다 |
| 남은 몰입 여력 | 평소(기준선) 하루 몰입 중앙값 − 오늘 이미 한 몰입. 목표치가 아니라 자기 평소를 기준으로 삼는다 |
| 계획 실현 가능성 | 남은 계획의 예상 합계 × 추정 편향(최근 30일 중앙값, 표본 3개 이상일 때만)을 남은 몰입 여력과 견준 것 |

**Cadence 점수** = 몰입량(40) + 연속성(20) + 파편화 억제(15) + 방해 억제(15) + 세션 이행(10).

- 활동 기록이 5분 미만인 날은 점수를 매기지 않습니다.
- **미분류가 활동의 절반을 넘는 날**은 점수를 흐리게 두고 이유를 함께 적습니다. 미분류 시간은
